# DOP Agent Portal — RD Collection & Submission Workflow

**Source:** Agent-provided, step-by-step (the real process on `dopagent.indiapost.gov.in`).
**Status:** Authoritative. This is the spec the "online submission + reference" work is built against.

---

## The end-to-end workflow (what the agent actually does)

1. **Login** — open the RD agent portal, enter Agent ID + password → Login.
   - First login forces a password change.
   - **Max 10 unsuccessful attempts** before lockout (why the app caps auto-submits at 2).

2. **Navigate** — **Accounts** tab → **Agent Inquire and Update** → the list of accounts attached to the agent.

3. **Select mode of payment** — **Cash**, **DOP cheque**, or **Non-DOP cheque**.

4. **Select the accounts to pay** — tick the account numbers being paid this list.
   - Accounts are in **ascending order across pages**; the agent pages through and ticks each (e.g. acct #1 on page 1, next on page 3, …).
   - Then click **Save**.
   - **Limits:** max **50 accounts per list**; **₹20,000 cap for Cash**; **no amount limit for Cheque**.

5. **Selected-accounts screen** — the portal lists the ticked accounts with a **Modified** column (starts "NO").

6. **Enter installments per account** (one record at a time):
   - **Cash:** select the account → enter **no. of installments** → click **Get Rebate and Default** (portal auto-computes default penalty + advance rebate) → enter the customer's **ASLAAS number** → **Save**.
   - **DOP / Non-DOP cheque:** select the account → enter **installments**, **cheque number**, **bank account number on the cheque**, **ASLAAS number** → **Save**.
   - On save: *"installment saved successfully"* and that record's **Modified** column flips to **YES**.
   - Repeat until **Modified = YES for every record**.

7. **Pay all** — click **Pay All Modified Installments**. The portal generates a **reference number**, prefixed by mode:
   - **C** = Cash · **DC** = DOP cheque · **NDC** = Non-DOP cheque.

8. **Reports** — click **Reports** → enter the **list reference number** → set **Status = Success** → **Search** → **OK**.

9. **PDF** — the portal generates the official schedule PDF. **Print 2 copies, submit at the counter.**

## Rules & limits (authoritative)

| Rule | Value |
|---|---|
| Max accounts per list | **50** |
| Cash list cap | **₹20,000** |
| Cheque list cap | **none** |
| Login attempts before lockout | **10** |
| Reference prefix | **C** (cash) · **DC** (DOP cheque) · **NDC** (non-DOP cheque) |
| Rebate (advance) + default (penalty) | **auto-computed by the portal** ("Get Rebate and Default") |
| Cheque extra fields | cheque number + bank account number (per account) |
| Official PDF | generated by the portal's **Reports** search on the reference, status Success |

## Build plan — the missing pieces (steps 5–9)

Pinned to the captured markup in `recon/` (see `recon/README.txt`):

1. **Installment automation (step 6)** — after Save, for each account: fill installments, click *Get Rebate and Default*, read back the computed rebate/default, fill ASLAAS, Save; confirm *Modified = YES*. Cheque mode also fills cheque no. + bank account no.
   - Needs: `recon/portal_02_installment_entry.html`.
2. **Pay All + capture reference (step 7)** — click *Pay All Modified Installments*, read the generated **C/DC/NDC reference number**, store it on the `Lot`.
   - Needs: `recon/portal_03_pay_all_reference.html`.
3. **Official PDF via Reports (steps 8–9)** — Reports → enter ref → Status Success → Search → capture/download the portal PDF (this replaces the app's draft as the counter copy).
   - Needs: `recon/portal_04_reports_pdf.html`.

### Data-model changes this implies
- `LotItem`: add optional **`chequeNumber`** and **`bankAccountNumber`** (cheque modes); optionally store portal-computed **rebate** and **default** per line.
- `Lot`: add **`referenceNumber`** (the real C/DC/NDC ref, null until submitted) and a **`submittedAt`** timestamp; keep the local `L…` id only as an internal handle.
- `LotPacking`: enforce **max 50 accounts/list**, and apply the **₹20,000 cap for Cash only** (no cap for cheque).

### UX implications (already partly done)
- The app's printed report is now a **DRAFT working copy** ("not an official receipt; the E-Banking reference and certified schedule are issued by the portal on submission"). Once real submission + Reports PDF land, the official PDF becomes the counter copy and the draft stays a keying aid.
- Once a `Lot` has a real reference, show it as **"Ref: C…/DC…/NDC…"**; until then show **"Local list · not submitted"**.

## Captured selector map (from recon/, Finacle form `CustomAgentRDAccountFG`)

All four screens resolved. Real captured values (a live reference, customer
ASLAAS/account numbers) stay in the git-ignored `recon/` files — only the
selector names are recorded here.

**Step 6 — installment entry (`portal_02_installment_entry.html`):**
- Select a record: radio `CustomAgentRDAccountFG.SELECTED_INDEX` (value = 0-based row).
- Installments: text `CustomAgentRDAccountFG.RD_INSTALLMENT_NO` (defaults to 1).
- Cheque modes only: `RD_CHEQUE_NO`, `RD_ACCOUNT_NUMBER_FOR_PAYMENT` (bank a/c on the cheque), `BANK_NAME_RDI`.
- Get Rebate & Default: submit `Action.CALCULATE_REBATE` (value "Get Rebate & Default Fee") — portal fills rebate/default.
- Save this record: submit `Action.ADD_TO_LIST` (value "Save") → the row's **Modified** cell flips NO→YES.
- Mode: select `CustomAgentRDAccountFG.MODE_RD_PAYMENT` (C/DC/NDC) — **disabled here** (locked from the list page).
- **ASLAAS is NOT entered here** — it's a pre-stored, read-only column (`ASLAAS_NO_ARRAY[i]`), managed via the "Update ASLAAS Number" menu. It is **per account** (each row has a different number), so the app *reads* it here (`readAslaasNumbers()`) after a prepare/submit and stores it on the account; lists print each account's own number.
- Other actions on this screen: `Action.DELETE_SAVED_RECORD` (Delete), `Action.BACK_TO_ACCOUNT_LIST` (Back).

**Step 7 — Pay All (`portal_02` → result `portal_03_pay_all_reference.html`):**
- Money-committing: submit `Action.PAY_ALL_SAVED_INSTALLMENTS` (value "Pay All Saved Installments").
- Result page shows the generated **reference number**: mode prefix (`C`/`DC`/`NDC`) + 9 digits.

**Steps 8–9 — Reports → official PDF (`portal_04_reports_pdf.html`):**
- Reference box: `CustomAgentRDAccountFG.EBANKING_REF_NUMBER`.
- Status dropdown: `CustomAgentRDAccountFG.INSTALLMENT_STATUS` (set to Success).
- Search: submit `Action.SEARCH_INSTALLMENT_DETAILS` (value "Search").
- Download format: select `CustomAgentRDAccountFG.OUTFORMAT` (option value **`5` = PDF**).
- Generate/download: submit `Action.GENERATE_REPORT` (value "OK", `data-isdownloadbutton="true"`).

## Safety note on building this
Steps 6 and 8–9 change portal draft state / are read-only; **step 7 (Pay All) commits
real money and cannot be tested against the live portal from here.** Recommended
build order: (C) Reports-PDF-by-reference first — read-only, immediately replaces
the app's DRAFT with the official PDF once the agent has a reference; then (A)
installment-entry automation (reversible via Delete/Clear); keep (B) Pay All
**manual** (agent taps it after review) until it can be verified on his phone.
